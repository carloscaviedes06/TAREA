# Trabajo Colaborativo y Control de Versiones

## Integrantes del Equipo
* Carlos Caviedes
* Beren Quinga

## Flujo de Trabajo Seguido
1. El líder creó el repositorio base en GitHub con el archivo README inicial.
2. Se añadieron a los compañeros como colaboradores del proyecto.
3. Cada integrante creó una rama independiente (`rama-nombre`) para trabajar de forma aislada.
4. Cada miembro subió archivos individuales realizando al menos 2 commits con mensajes descriptivos.

## Manejo y Resolución de Conflictos
Para simular el conflicto, dos integrantes modificaron la primera línea del archivo README de manera simultánea en ramas distintas. Al intentar realizar el Merge de la segunda rama, GitHub detectó el choque de versiones.

* **Cómo se resolvió:** Se utilizó la herramienta web de resolución de conflictos de GitHub, analizando el código en equipo, removiendo las etiquetas de conflicto (`<<<<<<<`, `=======`) y consolidando una versión final unificada.
